# API 키 파일과 실제 연결 검증

API 키 파일을 제공하면 로컬에서 읽어 앱의 Keychain에 저장하거나 합성 자료로 실제 연결을 검증할 수 있다. 파일이 있다는 사실만으로 모델 접근 권한·프로젝트 사용 한도·분류 품질이 확인되지는 않는다. 정식 앱 배포에 필요한 Apple Developer ID와 공증 자격도 API 키와 별개다.

## 파일 형식

저장소 밖의 경로, 예를 들어 `~/.config/neatree/openai-api-key.txt`에 **API 키만 한 줄**로 저장한다. UTF-8 텍스트나 TextEdit의 RTF 문서를 사용할 수 있다. `OPENAI_API_KEY=`, 따옴표, 설명이나 다른 키를 함께 넣지 않는다. 마지막 줄바꿈과 UTF-8 BOM은 허용한다. 채팅·Git·셸 명령 인자에는 키 내용을 넣지 않는다.

텍스트 편집기로 파일을 저장한 뒤 소유자만 읽을 수 있도록 권한을 제한할 수 있다.

```sh
chmod 600 "$HOME/.config/neatree/openai-api-key.txt"
```

앱은 지정한 파일만 읽는다. 디렉터리를 검색하거나 `.env`를 자동 탐색하지 않는다. 파일 컨테이너는 최대 64KiB, 서식을 제거한 텍스트는 최대 8KiB다. RTF는 macOS의 문서 디코더로 텍스트만 읽고 그 전체 내용이 키 한 줄인지 확인한다. 문서에서 키처럼 보이는 일부 문자열만 추출하지 않는다. 최종 경로가 심볼릭 링크인 파일, 일반 파일이 아닌 대상, 여러 줄의 내용은 거부한다. `.rtfd` 폴더는 지원하지 않는다. 오류에는 파일 경로나 키 내용을 넣지 않는다. API 키의 접두사만으로 진위를 판단하지 않는다.

## Keychain에 가져오기 — API 호출 없음

앱의 **설정 → OpenAI API → 키 파일 가져오기**에서 준비한 UTF-8 텍스트 또는 RTF 파일을 선택한다. 키를 직접 입력하려면 같은 화면의 보안 입력란과 저장 버튼을 사용한다. 가져오기와 저장은 Keychain에 키를 보관하며 API를 호출하지 않는다. 데모 실행에서는 개인 API 키를 가져오거나 저장하지 않는다.

개발용 CLI를 사용할 때는 저장소 루트에서 실행한다.

```sh
swift run organizer key import --file "$HOME/.config/neatree/openai-api-key.txt"
swift run organizer key status
```

키는 기존 앱과 같은 Keychain 항목에 저장된다. 출력에는 저장 여부만 표시한다. 원본 파일을 변경하거나 자동 삭제하지 않으며, 저장 명령 자체는 네트워크 요청을 보내지 않는다. 가져온 뒤 원본 파일을 계속 보관할지는 사용자가 정한다. `key status`의 “설정됨”은 연결 성공을 의미하지 않는다.

앱 시작과 `key status`는 키의 실제 값을 읽지 않고 Keychain 항목의 메타데이터로 등록 여부만 확인한다. 이 확인에서는 인증 창을 띄우지 않으며, 앱은 확인을 메인 스레드 밖에서 수행해 첫 화면을 막지 않는다. 인증이 필요한 항목은 확인 대상에서 건너뛴다. 따라서 “설정됨”은 현재 실행 파일이 키의 실제 값에 접근할 수 있다는 보증도 아니다. 분석이나 연결 확인처럼 실제 API를 사용하는 작업에서는 키를 읽으며, 이때 macOS가 Keychain 접근 허용을 요청할 수 있다. 키 저장·가져오기·삭제 역시 사용자가 실행하는 별도 Keychain 작업이다.

기존 `key set`의 화면에 표시하지 않는 터미널 입력과 `OPENAI_API_KEY` 환경변수 방식도 유지된다. 환경변수가 지정되면 Keychain보다 우선한다.

## 합성 자료로 실제 API 검증 — 명시적 실행 시 비용 발생

앱의 **설정 → OpenAI API → 연결 확인**을 누르면 호출 범위와 비용 발생 여부를 먼저 보여준다. **최대 2회 호출로 확인**을 선택하면 아래와 동일한 합성 자료 검증을 실행하고 설정 화면에 단계별 결과·모델명·요청 횟수를 표시한다. 키를 가져오기만 한 상태와 연결·기본 분류를 확인한 상태는 구분한다.

CLI에서는 다음 명령을 사용한다.

```sh
swift run organizer api verify --allow-paid-request
```

Keychain에 저장하지 않고 지정한 파일의 키로만 검증하려면 다음을 사용한다.

```sh
swift run organizer api verify --allow-paid-request \
  --key-file "$HOME/.config/neatree/openai-api-key.txt"
```

`--allow-paid-request`가 없으면 키 파일이나 Keychain을 읽기 전에 중단한다. 이 명령은 실제 OpenAI API를 사용하므로 호출자가 비용 발생을 승인한 경우에만 실행한다. 자동 개발 테스트는 이 명령을 실행하지 않는다.

검증은 코드에 들어 있는 합성 폴더 이름·파일명·청구서 문구만 사용한다. 실제 다운로드·문서·카탈로그·상태 저장소를 읽거나 파일을 이동하지 않는다.

1. 설정된 `gpt-6.1-sol` 모델에 구조 분석 요청을 보내 유효하고 비어 있지 않은 규칙 후보를 확인한다.
2. 첫 단계가 성공하면 합성 청구서를 보내 청구서 폴더와 유효한 파일명을 제안하는지 확인한다.

최대 두 번의 요청을 보내며 실패 후 자동 재시도하지 않는다. 요청당 최대 출력 토큰은 1,536개로, 두 요청의 출력 상한 합계는 3,072개다. 이는 **금액 한도가 아니다**. 입력·추론 토큰과 계정별 모델 요금이 영향을 줄 수 있으며, 응답의 `usage`가 있으면 입력·출력·총 토큰 수를 JSON 보고서에 기록한다. 실제 비용은 계정의 사용 내역에서 확인한다. 기존 앱의 일반 분석은 기본 최대 출력 6,000개를 유지한다.

보고서는 모델명, 단계별 성공 여부, 시도 횟수, HTTP 상태와 토큰 수만 기록하며 키·전체 서버 오류 본문은 출력하지 않는다. 실패 시 종료 코드는 1이다. 이 합성 검증의 통과는 현재 키로 모델을 호출하고 구조화된 응답을 처리할 수 있다는 확인이며, 모든 실제 파일의 분류 품질을 보증하지 않는다.

## 실행 결과 해석

- `401`·`403`: 현재 키·프로젝트 권한을 확인한다.
- `404`: 설정한 모델 또는 API 접근 가능 여부를 확인한다. 모델 이름을 확인 없이 자동 대체하지 않는다.
- `429`: 프로젝트 한도·사용량 제한을 확인한다. 자동 재시도로 비용을 늘리지 않는다.
- 응답 미완료: 토큰 상한 또는 모델 응답 상태를 검토한다. 상한을 늘려 다시 호출하는 일도 별도 실행이다.
- 형식은 유효하지만 합성 기대 분류와 다름: 프롬프트·모델 제안 품질 검수가 필요하다.

실제 사용 검증은 이후 사용자가 지정한 비민감 샘플과 호출 한도 안에서 진행한다. 자동 파일 이동의 성공과 모델의 분류 정확도를 각각 확인해야 한다.

## 완료된 개발 검증과 추가 호출

2026-11-12 개발 작업에서 사용자가 승인한 **최대 5회 호출은 5회 모두 사용했다**. 구조 분석·청구서·모호한 자료·문서 속 지시·번호가 있는 회의록을 합성 자료로 확인했으며, 결과는 [실제 API 검증 기록](API_VALIDATION.md)에 있다. 이 승인에 남은 호출은 없다. 키 파일이 계속 있거나 Keychain에 저장되어 있다는 이유로 추가 개발 검증을 실행하지 않는다.

개발 중 다시 유료 검증이 필요하면 사용자에게 새 호출 범위와 한도를 승인받아야 한다. 앱에서 사용자가 직접 **연결 확인 → 최대 2회 호출로 확인**을 선택하는 동작도 새 유료 실행이다. 이전 검증의 성공 표시나 이번 5회 한도에 포함되어 무료로 재실행되는 기능이 아니다. 일반 파일 분석과 자동 분석 역시 별도 API 사용이며, 합성 연결 확인을 통과한 뒤에도 사용자의 실제 파일 전송 선택을 따른다.
