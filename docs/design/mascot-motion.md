# 실로(Psilo)의 배치와 행동

2026-11-11 사용자 요구사항과 현재 구현 기록. 배치는 승인됐고, 모델은 후속 요청에 따라 Blender 3D로 제작했다. 구현 여부와 최종 외형·모션 검수는 구분한다.

## 승인된 배치

- 파일이 없는 화면은 [시안 3](mascot-empty-v1.png)처럼 목록 중앙에 큰 실로와 안내 문구를 배치한다.
- 파일이 있는 화면은 [시안 1](mascot-sidebar-v1.png)처럼 사이드바 하단에 작은 실로를 배치한다.
- 한 창에 같은 캐릭터를 중복 표시하지 않는다. 실제 검토함 전체가 비었는지 판단하며 검색 결과만 비었다고 중앙 배치로 바꾸지 않는다.
- 하나의 렌더러를 유지한 채 위치와 크기를 바꾼다. 새 캐릭터가 등장한 것처럼 행동 상태를 초기화하지 않는다.
- 설정 화면이 표시될 때는 본창 캐릭터를 쉬게 한다. 캐릭터와 소품은 클릭·드래그·키보드 입력을 가리지 않는다.

## 행동과 연속 전환

| 상태 | 행동 |
| --- | --- |
| 평상시 | 멍한 기본 표정, 느린 호흡과 간헐적인 눈 깜빡임. 앱 창 안의 커서를 눈이 먼저 보고 고개가 조금 늦게 따라간다. |
| 파일·폴더 분석 및 정리 시작 | 주의를 작업으로 돌리고 주변 파일 세 개가 정해진 곡선을 따라 순서대로 모인다. 안경은 얼굴 위에서 내려와 안착한다. |
| 작업 중 | 안경과 소품을 유지하고 파일 쪽으로 시선을 움직이며 고개를 조금 숙인다. 커서 추적은 파일을 살펴보는 행동에 양보한다. |
| 완료 | 뿌듯한 입 모양과 짧은 들썩임·으쓱 동작을 보이고, 안경과 소품이 물러난 뒤 약 2.5초의 축하 행동을 마치고 대기로 돌아간다. 문구는 실제 결과를 계속 표시할 수 있다. |
| 오류 | 현재 자세에서 나선 눈이 나타나 회전하고 고개가 비틀거린다. 작업 중 오류라면 이미 모인 파일과 안경을 유지한다. 문제가 해결되면 균형을 잡고 돌아온다. |
| 취소 | 성공 연출 없이 대기로 돌아간다. |

앱은 USDZ의 개별 부위에 연속 감쇠 스프링을 적용한다. 목표 상태가 바뀌어도 현재 자세와 속도를 유지하며 다음 자세로 이어간다. 갓을 따라가는 모자와 뿔은 조금 늦게 반응한다. 안경·눈·입·파일은 위치·기울기·크기를 연속적으로 바꾸고, 보이지 않을 때는 해당 엔티티를 비활성화한다.

빠른 작업 완료와 중간 취소도 현재 포즈에서 이어진다. 묶음 처리의 진행 갱신마다 안경 착탈과 파일 도착을 재시작하지 않는다. 완료 동작 중 새 작업이 시작되면 작업으로 전환한다. 실패 결과는 축하 동작보다 우선하며, 해결을 위한 재시도 중에는 작업 행동을 보여준다.

## 실제 앱 상태와 연결

`PsiloActivity`는 작업 ID, 종류, 진행, 성공·실패·취소 및 결과를 전달한다. `PsiloIssue`는 해결되지 않은 작업 오류를 별도로 보존한다. `isBusy`나 화면 문구를 해석해 행동을 결정하지 않는다.

- 파일 분석, 기존 구조 분석, 실제 정리, 되돌리기를 구분한다. 다운로드 감시 폴링이나 설정 저장만으로 작업 행동을 시작하지 않는다.
- 제안 준비, 규칙 후보 준비, 파일 이동 완료, 원위치 복구를 다른 결과로 전달한다. 제안이 준비된 것을 실제 파일 정리 완료라고 표현하지 않는다.
- 묶음의 일부 실패도 오류로 전달한다. 취소되거나 새 작업으로 교체된 작업의 늦은 결과는 현재 상태를 덮지 않는다.
- 오류 알림을 닫아도 미해결 오류는 남는다. 같은 종류의 작업에서 성공한 재시도 대상만 미해결 목록에서 제외하고, 남은 실패 대상이 없으면 오류를 해제한다. 개별 재시도와 부분 성공을 누적하며 관련 없는 작업의 성공은 오류를 지우지 않는다.

## Blender 제작과 앱 재생

실로는 넓고 낮은 산호색 갓, 세 개의 아이보리 반점, 둥근 큰 뿔, 정원사 모자와 짧은 받침 몸을 가진 비인간형 캐릭터다. 실제 Blender 5.3 장면에 편집 가능한 메시·곡선·모디파이어·재질을 만들고, Blender MCP로 장면 조회, 포즈 편집, 키프레임 추가와 미리보기를 수행했다. 제작 과정에는 `bpy` 보조 코드도 사용한다.

Blender의 키프레임은 작업·완료·오류 포즈를 확인하는 제작용 미리보기다. 앱은 이를 순서대로 재생하거나 PNG를 교체하지 않는다. 중립 USDZ를 불러와 부위별 연속 포즈를 계산한다. 자세한 원본과 내보내기 계약은 [자산 안내](../../assets/psilo/README.md)를 따른다.

## 가볍게 유지하는 기준

| 사용자 요구 | 현재 구성 |
| --- | --- |
| 단순한 모델과 소품 | 캐릭터 하나와 파일 세 개. 삼각형 22,780개·메시 27개·재질 6개·768×768 텍스처 1개, USDZ 630,244바이트. |
| 필요할 때만 렌더링 | 창 닫힘·최소화·앱 숨김·완전 가림·표시 해제 시 RealityKit `ARView`와 프레임 구독을 제거한다. 모델과 포즈는 보존하고 다시 보이면 뷰를 만든다. |
| 가벼운 움직임 | 파일은 미리 정한 Bézier 경로와 스프링으로 이동한다. 물리·충돌 계산을 추가하지 않는다. |
| 절제된 효과 | 앱에서는 방향광 하나, 실시간 그림자 없음. 본창은 중앙 약 144×114pt, 사이드바 약 88×76pt의 작은 뷰포트로 표시한다. |

macOS 14의 `ARView`에는 이 구현에서 사용할 공개 일시정지 API가 없어 렌더링 뷰 자체를 해제한다. 프레임 시간 적분 안정화를 위한 제한을 실제 30fps 렌더링 제한으로 설명하지 않는다. 기기별 FPS·GPU 사용률·전력 소비는 별도 측정 대상이다.

커서 추적은 소속 창의 로컬 마우스 이벤트만 사용하고 앱이 활성화되어 있을 때 반응한다. 전역 입력 감시 권한을 요구하지 않는다. 동작 줄이기에서는 비행·고개 회전·비틀거림과 깜빡임을 줄이고 표정·상태 문구를 남긴다.

## 검증 상태

- Blender 모델의 `usdchecker --arkit` 검증과 macOS 앱의 Debug·Release 빌드가 통과했다. 원본 내보내기·소스 리소스·Release 번들의 USDZ 해시가 일치한다.
- AppSupport 테스트 32개가 통과했다. 실로 관련 테스트 10개는 결과 구분, 취소·늦은 응답, 부분 실패, 오류 알림과 실제 복구의 분리, 개별 재시도·부분 성공에 따른 미해결 대상 갱신을 검증한다.
- Blender MCP에서 대기·작업·완료·오류·복귀 포즈를 실제 장면으로 조회했다. [MCP 포즈 확인 이미지](psilo-blender-mcp-poses.png)는 Blender 장면을 조회한 결과다.
- 네이티브 앱에서 사이드바 모델과 동작 확인 창의 안경·파일 소품, 오류의 회전 눈을 확인했다. 복구와 완료 이벤트는 접근성 상태와 런타임 로그로 확인했다. 최소화·앱 가리기 때 렌더러 해제, 창 복원 때 재개 로그를 확인했다. 샘플 이벤트만 사용했으며 실제 파일이나 API에는 접근하지 않았다.
- 중앙 빈 상태의 최종 배치와 시선·으쓱·비틀거림의 세부 타이밍에 대한 사용자 모션 검수는 남아 있다. 정지 화면과 상태 로그를 프레임 속도·전력 측정 또는 모든 전환의 시각 검수로 취급하지 않는다.
