# 실로(Psilo)의 배치와 행동

2026-11-12 기준 사용자 요구사항과 현재 구현 기록. 배치와 v7 뿔 형태는 승인됐으며, 사용자의 후속 요청으로 v7 전체 모델을 앱용으로 변환해 연결했다. 구현 여부와 캐릭터 전체 외형·모션의 최종 사용자 검수는 구분한다.

## 승인된 배치

- 파일이 없는 화면은 [시안 3](mascot-empty-v1.png)처럼 목록 중앙에 큰 실로와 안내 문구를 배치한다.
- 파일이 있는 화면은 [시안 1](mascot-sidebar-v1.png)처럼 사이드바 하단에 작은 실로를 배치한다.
- 한 창에 같은 캐릭터를 중복 표시하지 않는다. 실제 검토함 전체가 비었는지 판단하며 검색 결과만 비었다고 중앙 배치로 바꾸지 않는다.
- 하나의 렌더러를 유지한 채 위치와 크기를 바꾼다. 새 캐릭터가 등장한 것처럼 행동 상태를 초기화하지 않는다.
- 설정 화면이 표시될 때는 본창 캐릭터를 쉬게 한다. 캐릭터와 소품은 클릭·드래그·키보드 입력을 가리지 않는다.

## 행동과 연속 전환

| 상태 | 행동 |
| --- | --- |
| 평상시 | 멍한 기본 표정, 느린 호흡과 간헐적인 눈 깜빡임. 앱 창 안의 커서를 눈이 먼저 보고 고개가 조금 늦게 따라간다. |
| 파일·폴더 분석 및 정리 시작 | 주의를 작업으로 돌리고 주변 파일 세 개가 정해진 곡선을 따라 순서대로 모인다. 안경은 얼굴 위에서 내려와 안착한다. |
| 작업 중 | 안경과 소품을 유지하고 파일 쪽으로 시선을 움직이며 고개를 조금 숙인다. 커서 추적은 파일을 살펴보는 행동에 양보한다. |
| 완료 | 뿌듯한 입 모양과 짧은 들썩임·으쓱 동작을 보이고, 안경과 소품이 물러난 뒤 약 2.5초의 축하 행동을 마치고 대기로 돌아간다. 문구는 실제 결과를 계속 표시할 수 있다. |
| 오류 | 현재 자세에서 나선 눈이 나타나 회전하고 고개가 비틀거린다. 작업 중 오류라면 이미 모인 파일과 안경을 유지한다. 문제가 해결되면 균형을 잡고 돌아온다. |
| 취소 | 성공 연출 없이 대기로 돌아간다. |

앱은 USDZ의 개별 부위에 연속 감쇠 스프링을 적용한다. 목표 상태가 바뀌어도 현재 자세와 속도를 유지하며 다음 자세로 이어간다. 모자는 갓을 조금 늦게 따라간다. 뿔은 갓에 고정되어 밑동이 미끄러지지 않는다. 안경·눈·입·파일은 위치·기울기·크기를 연속적으로 바꾸고, 보이지 않을 때는 해당 엔티티를 비활성화한다.

빠른 작업 완료와 중간 취소도 현재 포즈에서 이어진다. 묶음 처리의 진행 갱신마다 안경 착탈과 파일 도착을 재시작하지 않는다. 완료 동작 중 새 작업이 시작되면 작업으로 전환한다. 실패 결과는 축하 동작보다 우선하며, 해결을 위한 재시도 중에는 작업 행동을 보여준다.

## 실제 앱 상태와 연결

`PsiloActivity`는 작업 ID, 종류, 진행, 성공·실패·취소 및 결과를 전달한다. `PsiloIssue`는 해결되지 않은 작업 오류를 별도로 보존한다. `isBusy`나 화면 문구를 해석해 행동을 결정하지 않는다.

- 파일 분석, 기존 구조 분석, 실제 정리, 되돌리기를 구분한다. 다운로드 감시 폴링이나 설정 저장만으로 작업 행동을 시작하지 않는다.
- 제안 준비, 규칙 후보 준비, 파일 이동 완료, 원위치 복구를 다른 결과로 전달한다. 제안이 준비된 것을 실제 파일 정리 완료라고 표현하지 않는다.
- 묶음의 일부 실패도 오류로 전달한다. 취소되거나 새 작업으로 교체된 작업의 늦은 결과는 현재 상태를 덮지 않는다.
- 오류 알림을 닫아도 미해결 오류는 남는다. 같은 종류의 작업에서 성공한 재시도 대상만 미해결 목록에서 제외하고, 남은 실패 대상이 없으면 오류를 해제한다. 개별 재시도와 부분 성공을 누적하며 관련 없는 작업의 성공은 오류를 지우지 않는다.

## Blender 제작과 앱 재생

실로는 넓고 낮은 산호색 갓, 세 개의 아이보리 반점, 둥근 큰 뿔, 정원사 모자와 짧은 받침 몸을 가진 비인간형 캐릭터다. 실제 Blender 5.3 장면에 편집 가능한 메시·곡선·모디파이어·재질을 만들고, Blender MCP로 장면 조회, 포즈 편집, 키프레임 추가와 미리보기를 수행했다. 제작 과정에는 `bpy` 보조 코드도 사용한다.

Blender의 키프레임은 작업·완료·오류 포즈를 확인하는 제작용 미리보기다. 앱은 이를 순서대로 재생하거나 PNG를 교체하지 않는다. 중립 USDZ를 불러와 부위별 연속 포즈를 계산한다. 자세한 원본과 내보내기 계약은 [자산 안내](../../assets/psilo/README.md)를 따른다.

현재 앱 리소스는 [v7 앱용 자산](../../assets/psilo/runtime-v7/README.md)의 `Psilo.usdz`다. 제작 원본은 `review-v7-plump-horns/Psilo-v7.blend`이며, Y-up·+Z 정면·미터 단위로 부위와 표정 변형을 함께 변환한다. 이전 `blender/`의 소형 모델과 v2–v6 검수 파일은 제작 이력으로 보존한다.

## 얼굴 표정과 호환 경로

`PsiloExpressionRig`는 갓과 함몰된 입의 `SmileClose`, 양쪽 눈의 `Happy`를 네 채널로 연결한다. 입의 열린 표면을 다른 얼굴로 교체하지 않고 같은 메시를 닫아 간다. 미소 선은 입이 거의 닫힌 뒤 연속적으로 나타나며, 각 채널의 진행 값은 본체와 같은 완료 스프링에서 받는다.

- macOS 15 이상에서도 실제 가져온 메시에서 **비어 있지 않은 변형 오프셋**과 `BlendShapeWeightsComponent`의 이름·인덱스 매핑을 모두 확인한 채널만 네이티브 가중치를 사용한다. 정점·변형 값은 유한한지 확인한다. 이름과 가중치 숫자만 존재하는 가져오기 결과는 네이티브 채널로 인정하지 않는다.
- macOS 14 또는 변형 오프셋·이름 매핑을 확인하지 못한 채널은 같은 토폴로지의 대상 메시로 위치와 법선을 보간한다. 따라서 macOS 15 이상에서도 호환 경로를 사용할 수 있다. 정점 수, 삼각형 인덱스, UV, 재질 인덱스와 유한한 좌표가 일치해야 이 경로를 연결한다. 가져온 공유 메시를 직접 바꾸지 않고 독립 메시를 만든다.
- 호환용 `PsiloMorphTargets`는 데이터를 읽은 뒤 장면에서 제거하므로 캐릭터와 함께 그려지지 않는다. 표정이 변하는 동안에만 약 30Hz 상한으로 메시를 갱신하고, 0·1 끝 상태는 즉시 반영한다. 안정된 표정이나 렌더러가 해제된 상태에서는 메시 교체 작업이 없다. 이는 화면 전체의 렌더링 FPS 제한이 아니다.
- 초기 연결에서 네 채널이 모두 준비되지 않으면 일부 얼굴만 닫지 않고 중립 표정을 유지하며 미소 선도 표시하지 않는다. 호환 메시 갱신 도중 오류가 발생하면 해당 채널의 후속 갱신을 중단한다. 이를 모든 기기에서 실패 없이 움직인다는 보장으로 해석하지 않는다.

개발용 `--psilo-mesh-morph-demo`는 최신 macOS에서 호환 경로를 강제로 선택해 검증하는 DEBUG 옵션이다. 이 결과가 실제 macOS 14 기기 검증을 대신하지는 않는다.

## 재질과 화면 색상

색상·거칠기·노멀을 베이크한 종이 재질과 단순한 방향광을 사용한다. `PsiloRenderStyle`은 v7 재질의 저반사 specular 값과 Blender AgX 표시 응답을 연결한다. [색상 변환 표](../../assets/psilo/runtime-v7/color-transform/README.md)는 Blender의 실제 출력에서 생성한 33³ RGBA half-float 표이며, 모델의 색상 텍스처와 별도 리소스다. 표에는 제작 화면의 +0.4 EV가 포함되고 현재 런타임의 +1.2 EV 조명 보정은 셰이더에서 별도로 적용한다.

색 공간은 창의 설정만으로 가정하지 않는다. 렌더러 생성 후와 창의 화면·배율 속성 변경 시, 해당 렌더러의 메모리 내 스냅샷 ICC 프로파일을 확인한다. 알려진 sRGB·Display P3 프로파일과 선형 읽기·쓰기를 다루는 지원 형식에서만 변환한다. 지원 형식은 `bgra8Unorm_srgb`, `rgba8Unorm_srgb`, `rgba16Float`이며, 현재 개발 기기의 화면은 `bgra8Unorm_srgb`(81), 비 HDR 스냅샷은 `rgba16Float`(115)로 관측됐다. 이는 모든 float/HDR 버퍼를 지원한다는 뜻이 아니다. P3 경로는 선형 색을 Rec.709로 옮겨 표를 적용한 뒤 P3로 되돌린다. 알파를 풀고 색을 변환한 뒤 다시 곱해 투명한 가장자리를 유지한다. 알 수 없는 프로파일·지원 범위 밖 형식과 일반 UNORM은 원래 렌더러 출력을 그대로 통과시킨다.

프레임마다 수행하는 추가 작업은 작은 GPU 연산 패스 하나다. 파이프라인과 표 텍스처는 기기·리소스별로 재사용한다. 프로파일 상태는 뷰마다 분리하고 잠금으로 보호하며, 종료된 뷰의 늦은 스냅샷 결과는 폐기한다. 프로파일 확인용 스냅샷은 파일로 저장하지 않고 매 프레임 생성하지 않는다. DEBUG 캡처 옵션의 명시적 파일 출력은 이 경로와 별개다.

## 가볍게 유지하는 기준

| 사용자 요구 | 현재 구성 |
| --- | --- |
| 단순한 모델과 소품 | 캐릭터 하나와 파일 세 개. 표시 메시 41,219 삼각형, 렌더링하지 않는 호환 표정 대상 24,935 삼각형, 재질 2개. 색상 2048²·거칠기 1024²·노멀 1024² 텍스처 3개. USDZ 5,014,102바이트와 색상 변환 표 287,496바이트. |
| 필요할 때만 렌더링 | 창 닫힘·최소화·앱 숨김·완전 가림·표시 해제 시 RealityKit `ARView`와 프레임 구독을 제거한다. 모델과 포즈는 보존하고 다시 보이면 뷰를 만든다. |
| 가벼운 움직임 | 파일은 미리 정한 Bézier 경로와 스프링으로 이동한다. 물리·충돌 계산을 추가하지 않는다. |
| 절제된 효과 | 방향광 하나, 실시간 그림자 없음, 표시 중 색상 변환 GPU 패스 하나. 본창은 중앙 약 144×114pt, 사이드바 약 88×76pt의 작은 뷰포트로 표시한다. |

macOS 14의 `ARView`에는 이 구현에서 사용할 공개 일시정지 API가 없어 렌더링 뷰 자체를 해제한다. 모델·포즈와 재사용 가능한 GPU 파이프라인은 남지만 숨은 뷰포트나 프레임 구독은 유지하지 않는다. 프레임 시간 적분 안정화를 위한 제한을 실제 30fps 렌더링 제한으로 설명하지 않는다. 기기별 FPS·GPU 사용률·전력 소비는 별도 측정 대상이다.

커서 추적은 소속 창의 로컬 마우스 이벤트만 사용하고 앱이 활성화되어 있을 때 반응한다. 전역 입력 감시 권한을 요구하지 않는다. 동작 줄이기에서는 비행·고개 회전·비틀거림과 깜빡임을 줄이고 표정·상태 문구를 남긴다.

## 검증 상태

현재 v7 USDZ의 기하·표정 대상·유한 좌표 검사와 원본/앱 리소스 해시는 [런타임 자산 기록](../../assets/psilo/runtime-v7/README.md)에 있다. 네이티브 네 채널과 강제 호환 네 채널의 개발용 변형 경로 확인은 최종 배포 패키지 전체의 검수와 구분한다.

b12 실제 앱 화면에서는 가져온 가중치 이름이 있어도 변형 오프셋이 0개인 경우 완료 표정의 입이 닫히지 않았다. 이 결과에 따라 네이티브 채널의 오프셋 존재 검사를 필수로 바꾸고 해당 가져오기 결과를 검증된 대상 메시 경로로 연결한다. 네 채널의 호환 경로 선택과 실제 얼굴 변형이 최종 패키지에서 확인됐는지는 통합 검증 기록을 따른다. 단독 가져오기 검사에서 네이티브 가중치가 동작한 결과를 모든 앱 가져오기 경로의 보장으로 확대하지 않는다.

현재 개발 맥에서 화면·스냅샷의 위 두 Metal 형식과 Display P3 출력 프로파일을 확인하고 상수 색상·조명 없는 재질을 이용해 선형 읽기·쓰기 및 원색 변환 계약을 조사했다. 프로파일 감지·GPU 변환을 결합한 최종 앱의 시각 결과, 다른 화면 사이 이동, sRGB/사용자 지정 ICC, 실제 macOS 14·Intel 기기의 결과를 모두 확인했다고 주장하지 않는다. 최종 패키지의 실행·메뉴바 포커스·모션 검증 결과는 [통합 검증 기록](../VERIFICATION.md)의 해당 빌드 항목을 기준으로 한다.

캐릭터 전체 외형과 중앙 배치, 시선·으쓱·비틀거림의 세부 타이밍은 최종 사용자 검수 대상이다. 정지 화면·상태 로그·형식 검사로 모든 중간 동작의 시각 품질이나 전력·프레임 성능을 보증하지 않는다.

### 이전 빌드의 검증 기록

다음은 v7 전체 모델과 현재 색상 변환을 연결하기 전의 기록이다. 당시 통과한 내용을 새 패키지의 통과 결과로 재사용하지 않는다.

- 짧은 뿔 반영 후 Debug 개발 빌드 0.1.0-b8을 패키징했다. USDZ·메뉴바 템플릿의 소스와 앱 번들 해시가 일치하며, 로컬 ad-hoc 서명 검증을 통과했다. 네이티브 동작 창에서 대기, 안경·파일이 등장하는 분석, 나선 눈 오류, 복구, 폴더 분석과 완료 전환을 확인했다. 당시 변경은 뿔에 한정됐으며 정밀 제작용 v5 몸체 전체를 앱에 넣은 결과는 아니었다. [짧은 뿔 적용 기록](short-horns-implementation.md)

- Blender 모델의 `usdchecker --arkit` 검증과 macOS 앱의 Debug·Release 빌드가 통과했다. 원본 내보내기·소스 리소스·Release 번들의 USDZ 해시가 일치한다.
- AppSupport 테스트 32개가 통과했다. 실로 관련 테스트 10개는 결과 구분, 취소·늦은 응답, 부분 실패, 오류 알림과 실제 복구의 분리, 개별 재시도·부분 성공에 따른 미해결 대상 갱신을 검증한다.
- Blender MCP에서 대기·작업·완료·오류·복귀 포즈를 실제 장면으로 조회했다. [MCP 포즈 확인 이미지](psilo-blender-mcp-poses.png)는 Blender 장면을 조회한 결과다.
- 네이티브 앱에서 사이드바 모델과 동작 확인 창의 안경·파일 소품, 오류의 회전 눈을 확인했다. 복구와 완료 이벤트는 접근성 상태와 런타임 로그로 확인했다. 최소화·앱 가리기 때 렌더러 해제, 창 복원 때 재개 로그를 확인했다. 샘플 이벤트만 사용했으며 실제 파일이나 API에는 접근하지 않았다.
